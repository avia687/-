01

Product Vision

The problem. Money lives across 10–20 disconnected surfaces — two banks, three cards, PayPal, Apple/Google subscriptions, utility portals, insurance, Amazon, email invoices, SMS receipts. There is no single trustworthy answer to “where did my money go this month, and what’s coming up?” The best global tools don’t support Israeli banks; local tools are manual and clunky.

The vision. Instead of a dozen apps, you open one. Everything imports automatically, AI categorizes it, and it’s presented in a calm, premium interface that answers questions in plain language and quietly finds you money to save.

Design principles

Zero-effort ingestion

Manual entry is the exception, never the rule.

Trust before features

It touches money — security and correctness beat flash.

Explainable AI

Every category & insight is traceable and user-correctable.

Calm software

No dark patterns. Notifications earn their place.

Speed is a feature

Sub-second interactions everywhere.

Local-first correctness

ILS, Hebrew, RTL, Israeli banks — first-class, not bolted on.

04

Non-Functional Requirements

Performance

Dashboard <1.5s p75 · API reads <300ms p95 · NL answer <3s · 2k-row statement <20s.

Scalability

Designed for 1M users. Stateless API + autoscale, async queues, partition-friendly schema, read replicas.

Reliability

Exactly-once ingest via idempotency keys · retries + circuit breakers · dead-letter queues.

Availability

99.9% target · graceful degrade — AI down still imports as “uncategorized”.

Accessibility

WCAG 2.1 AA · full keyboard nav · reduced-motion · contrast in both themes.

i18n / l10n

Hebrew (RTL) + English at launch · locale-aware money/date/number.

Observability

Structured logs, tracing, metrics, SLO alerting, ingestion/AI dashboards.

Cost control

Cheap models for bulk categorize, premium for Q&A · caching · per-user quotas.

05

Database Design

PostgreSQL core · Redis cache/queues · S3 for receipts/reports · pgvector for merchant/transaction embeddings. ~16 core entities.

Key decisions

Money as integer minor units (never floats). Soft deletes + append-only audit logs. Postgres RLS scopes every query to user/household.

Dedup hash

hash(merchant + amount bucket + date bucket + account) collapses the same expense arriving from card, email & statement.

Learning without retraining

Per-user category_rules + embeddings — corrections compound, no per-user fine-tune.

Analytics at scale

Materialized monthly_category_totals; transactions partition by user/date as volume grows.

-- core spine users · households · household_members accounts · connections(tokens encrypted) transactions · transaction_splits · merchants categories · category_rules · subscriptions budgets · budget_categories · goals insights · notifications · documents ingestion_jobs · audit_logs
06

API Architecture

BFF pattern. Next.js server as primary API — tRPC internally for end-to-end types, plus a versioned public REST /api/v1 for future mobile & power users. Zod validates every contract. Long work runs on async workers, never blocking requests.

Cross-cutting

  • Idempotency-Key on every financial POST · cursor pagination for transactions
  • Per-user + per-IP rate limits (Redis) · stricter on assistant & ingestion
  • SSE streaming for assistant answers & ingestion progress · RFC 7807 errors

Event-driven ingestion pipeline

Source (bank webhook / email / upload) │ ▼ enqueue → Redis / BullMQ Normalizer clean · FX-convert · dedup(hash) │ Categorizer rules → embeddings → LLM fallback → confidence │ ├─▶ Subscription / Anomaly / Duplicate detectors ▼ Persist txn + refresh summaries → emit events │ ▼ Notifier / Insight generator
07

UX Flow

First-run activation — the “here’s your month” moment

Sign up (email / Google / Apple) → pick base currency + language (Hebrew / English) → Add first source: [ Connect bank ] [ Scan email ] [ Upload statement ] → Consent screen READ-ONLY · encrypted · what we access → Import runs — dashboard skeleton fills in real time → AI categorizes → first value → optional: set a budget, confirm detected subscriptions

Correction flow — the app gets smarter

Click a category → pick a new one → “Apply to 12 similar?” → creates a rule + updates the embedding → future transactions auto-fixed. A ⌘K command palette jumps anywhere and asks the assistant. Optimistic UI on every edit; empty states that teach.

11

Security Plan

This app touches money — security is the product. Read-only financial access; we never move money in the MVP, and we say so prominently.
Encryption

TLS in transit, AES-256 at rest, field-level envelope encryption (KMS) for tokens & PII. Tokens never logged.

AuthZ

MFA, OAuth, short-lived JWT + rotating refresh, Postgres RLS + app-layer checks (defense in depth).

Audit & abuse

Append-only audit logs, edge + app rate limits, login anomaly / impossible-travel detection.

AI safety

No cross-user data in prompts, PII minimization, prompt-injection defense on ingested email/receipt text.

Compliance

GDPR + Israeli Privacy Law · consent per integration · data export & delete · DPAs with subprocessors.

Backup / recovery

Encrypted backups + PITR, tested restore, RPO ≤15m / RTO ≤1h.

12

AI Features

Categorization — hybrid, cheap by default

1. rules user rules · known merchants · MCC free · instant · majority 2. embeddings nearest categorized txns (pgvector) cheap 3. LLM only low-confidence / unknown batched · cached ↳ user correction → new rule + embedding → accuracy compounds
Subscription detection

Recurring pattern → next-renewal prediction, price-increase, duplicate & unused flags.

Anomaly & duplicate

“3× your usual electricity bill”, double charges, potential fraud → insights + alerts.

Forecasting

Predict end-of-month total & per-category spend, feeding budget warnings.

NL assistant

NL → validated query plan → aggregation → Claude writes answer. Numbers come from the query layer, never invented.

Cost controls: model routing by task, caching, batching, per-user quotas, and graceful fallback if AI is unavailable.
